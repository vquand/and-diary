# Android pen diary

Build an offline diary for the Galaxy Tab S9 and S Pen. The app opens on the current month and scrolls vertically through month grids. Tapping a date opens one continuous sheet that grows downward. The sheet can contain multiple sections with different paper styles. A date gets a dot when it contains ink or an image. Entries autosave locally and support manual backup and restore.

## Stack decision

**First choice.** Prototype Rust + GPUI using `gpui-mobile`. Its Android touch translation leaves force unset, so use the platform-view embedding path to host an AndroidX Ink surface. The example host would need a small ink-view addition. Keep pressure-sensitive input and live rendering on Android. Send completed strokes and document edits to Rust. [GPUI touch input](https://github.com/itsbalamurali/gpui-mobile/blob/5fd54f4554263ae06753e90472c7f2e2ff5d7495/src/android/window.rs#L1484-L1495) · [Android platform views](https://github.com/itsbalamurali/gpui-mobile/blob/5fd54f4554263ae06753e90472c7f2e2ff5d7495/src/android/platform_view.rs) · [AndroidX Ink modules](https://developer.android.com/develop/ui/views/touch-and-input/stylus-input/ink-api-modules)

**Fallback.** Use Kotlin and Jetpack Compose for the Android shell, with the same AndroidX Ink surface. Rust owns the diary model, date index, persistence, and backup logic. Discord's Project Phoenix follows this architecture at a high level. It uses GPUI on desktop and shares Rust application code with native Android and iOS interfaces. [Discord's Project Phoenix announcement](https://www.youtube.com/watch?v=zgdPbgWaobQ) · [Discord CTO's architecture notes](https://x.com/svishnevskiy/status/2118081920194203799)

Pin the prototype dependencies. Check `craft-atomic` for the app's private entry files. `craft-ui` uses egui. XNotes is the reference for live-to-finished ink handoff and image handles. Use a round, soft Chinese brush with pressure-responsive width and tapered ends as the calligraphy target. [Craft Atomic](https://github.com/storytold/craft-libs/blob/2c81ed850319ef3504ce56d82379b346522af18e/crates/atomic/README.md) · [Craft UI manifest](https://github.com/storytold/craft-libs/blob/2c81ed850319ef3504ce56d82379b346522af18e/crates/ui/Cargo.toml) · [XNotes ink handoff](https://github.com/shardulvs/xnotes-android/blob/96357d873ac509e2a925e53b84eba9101d95994b/app/src/main/java/com/xnotes/canvas/FrontInk.kt#L23) · [XNotes image handles](https://github.com/shardulvs/xnotes-android/blob/96357d873ac509e2a925e53b84eba9101d95994b/app/src/main/java/com/xnotes/canvas/ResizeMath.kt#L224)

## Paper and ink

Start with four paper templates. Show a small preview in the paper picker so each guide pattern is recognizable.

- **Blank** for free writing and photos.
- **Ruled** for English handwriting, with faint horizontal lines.
- **Square grid** for everyday Chinese diary entries, with one character per box.
- **田字格** for Chinese brush practice, with faint horizontal and vertical center guides inside each square. [Chinese National Academy for Educational Research writing material](https://stv.naer.edu.tw/data/teach_module/%E5%9C%8B%E5%B0%8F%E4%BD%8E%E5%B9%B4%E7%B4%9A%E5%9C%8B%E8%AA%9E%E7%BF%92%E4%BD%9C-%E8%B2%93%E9%A0%AD%E9%B7%B9%E5%B0%8F%E5%AD%B8%E5%A0%82.pdf)

Let users choose guide spacing and paper color. Start with white, ivory, and pale grey swatches plus a custom color. Give each writing tool its own ink color, with swatches and a custom color. Save the chosen ink color on each stroke so a toolbar color change applies to new strokes. Use low-contrast guides that remain visible on the chosen paper color.

Choose a default paper style for the first section of new days. In the editor, use **Add section** to append an area with its own template, guide spacing, and paper color. For example, write a diary entry on ruled paper, then add a 田字格 section below for practice. The last section grows as the sheet fills. Change any section's style in place.

Store section boundaries and styles with the entry, including on a day with no ink or photos. Draw each section's background and guides within its bounds. Strokes and photos use shared sheet coordinates, so they can cross a section boundary and stay in place when a style changes. Keep the calendar dot tied to ink or photos. Include section boundaries, paper styles, and stroke colors in backup and restore.

## Build order

1. **Prove the writing surface.** Build an arm64 APK with one sheet, an everyday pressure pen, and the soft brush. Start from the `gpui-mobile` Android example. On the Tab S9, write `永`, small English script, quick dots, and slow light-to-heavy strokes. Rest a palm on the screen, scroll with a finger, rotate the tablet, and background and reopen the app. Verify clean tapers, no palm marks or stroke flicker, and stable surface placement and input after resuming. Compare pen lag with a minimal native AndroidX Ink host and check app PSS at idle and after opening the same ink-and-photo sample in each host. Keep GPUI if the experience holds up, memory is comparable or better, and the bridge stays small. Use the fallback if GPUI needs ongoing backend changes for stable inking or has a clear memory or latency penalty. Record the tablet's reported Android version during testing. Samsung lists One UI 8.5 for the Tab S9 under Android 16. [GPUI Android example](https://github.com/itsbalamurali/gpui-mobile/blob/5fd54f4554263ae06753e90472c7f2e2ff5d7495/example/README.md) · [Android memory checks](https://developer.android.com/topic/performance/memory/guide/tools-overview) · [Samsung firmware notes](https://doc.samsungmobile.com/SM-X710/026933230714/eng.html)
2. **Save and reopen a dated entry.** Store editable strokes and their brush settings in sheet coordinates. Add eraser and undo. Use S Pen for ink and fingers to scroll the growing sheet. Once saving works, add paper sections and ink settings. Test a ruled section followed by 田字格. Verify continuous scrolling, guides extending as the last section grows, and section styles and ink colors surviving an app restart. Keep the entry format independent of the UI shell.
3. **Connect the calendar.** Use local calendar dates as entry keys. Open directly into the selected date and return to the same month scroll position. Draw dots from the saved entry state without loading page contents. Check month and year boundaries, blank dates, and the dot clearing when the last item is removed.
4. **Add photos to the paper.** Paste an Android clipboard image or pick a photo. Store an app-owned copy. In selection mode, drag to move it and use a corner handle to resize it with its aspect ratio fixed. Decode previews to the visible size. Verify that an image-only day shows a dot and that the image and its geometry survive reopening the entry. [Android clipboard image access](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste)
5. **Back up and restore.** Export one file containing entries and their image assets. Validate the archive before importing. Preserve existing entries and report skipped dates when they conflict. Test a round trip into an empty diary and check that a damaged archive leaves existing entries usable.
